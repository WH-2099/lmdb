# 项目范围

[返回项目跟踪](README.md)

建立日期：2026-10-15。
状态：初步企划，第一阶段为广泛调研。

## 项目目标

构建精选、可追溯、可通过 Git 协作维护的模型元数据注册表。
长期覆盖各类模型，包括语言、多模态、图像、音频、视频、嵌入、重排、视觉及其他专业模型。
近期首先梳理模型基础信息，之后扩展提供方、托管平台和具体服务信息。
权重托管、基准评测执行和推理服务基础设施不属于当前项目目标。

## 需要研究的数据

- 身份：名称、发布者、原始 ID、别名、版本、生命周期和模型家族。
- 模态与任务：分别记录输入、输出和任务类型，避免用「多模态」覆盖所有差异。
- 基础规格：上下文、输入与输出上限、模型大小、权重形式、架构及公开的训练信息。
- 能力与限制：角色可接受的内容、工具调用、结构化输出、推理模式、流式或实时接口及条件组合。
- 关系：基础模型、微调、蒸馏、合并、量化和跨来源映射。
- 来源：字段所依据的官方文档、目录记录、获取时间和证据状态。
- 服务差异：同一模型在不同平台、端点、地区、版本上的支持范围，逐步扩展。

用户提出的 Gemini system prompt 图片限制是一条需要核实的研究问题。
具体支持矩阵由证据确定，不能从「支持图像输入」推导 system instruction 支持图像。

## 已确认的工程方向

- 审定元数据计划保存为 YAML，正式 schema 尚未决定。
- 性能敏感核心尽可能使用 Rust。
- 脚本优先 Python，采用实施时已发布的稳定版本语法并支持异步。
- 避免 Bash 脚本；少量命令执行不等于引入 Bash 工具链。
- 选择有维护基础和明确生态方向的技术，不把发布时间最新当作唯一依据。
- Python 依赖按根目录 [README](../README.md) 的 `pyproject.toml`、`uv.lock`、`requirements.txt` 约定维护。
- 第一阶段只进行调研和设计，以 Markdown 保存结果，暂不编写产品代码或固定正式 schema。

## 本阶段交付

1. 可持续更新的项目跟踪目录和树形索引。
2. 覆盖官方来源、聚合目录与不同模型类型的数据源地图。
3. 同类项目比较和必要的只读代码考察。
4. 特例建模、身份规范化、来源追踪和采集更新的架构候选。
5. Rust、Python、采集框架与存储方案的选择依据。
6. 下一阶段可验证的样本范围、待决策项及验收条件。

## 范围判断

「所有模型」适合作为扩展方向，目前没有可证明完整的全球模型目录。
调研建议按模型任务和来源覆盖率管理范围，而不承诺穷尽全部模型。
首批先用一小组代表性模型验证资料是否足够表达复杂限制，再决定扩大数据量。

## 尚待明确

| 问题 | 本轮默认处理 | 影响 |
| --- | --- | --- |
| 首要使用场景 | 暂以应用选型和接口兼容为重点，同时保留谱系与许可证 | 决定首批字段和来源排序 |
| 是否纳入价格 | 调查获取方式，暂作服务层候选 | 更新频率、货币和计费口径复杂度 |
| 是否记录实验结果 | 本轮只记录文档和目录证据 | 将来需要预算、环境和可复现条件 |
| 授权与数据再分发 | 逐来源确认，未知则保留链接与调查状态 | 决定哪些内容可以进入公开数据集 |
| 开源权重长尾 | 先调查分类、关系与采样方式 | 决定规模、去重及审核工作量 |

这些默认处理是可调整的研究假设。
