# 项目决定与待定事项

[返回项目跟踪](README.md) · [实现说明](../docs/data-model.md) · [研究档案](../research/2026-10-15/README.md)

更新日期：2026-10-19。
项目已实现 Rust CLI、来源数据、语义查询、官方页面字段核对与本地模型 API Mock 服务，研究档案中的候选方案保留为历史依据。
以下记录区分用户方向、已采用的实现选择和仍需验证的工作。

## 用户方向

| 编号 | 约束 | 当前落实方式 |
| --- | --- | --- |
| D01 | 先进行广泛调研，再进入实现 | 初始报告留在 `research/2026-10-15/`，当前阶段交付 CLI 与首批数据 |
| D02 | 长期覆盖各类模型，先模型层，再扩展平台 | 公开目录、跨任务精选样本与专业模型条件声明；平台事实保留独立作用域 |
| D03 | YAML、Git 审查与版本维护 | 来源目录、人工声明、身份、页面提取结果和采集配置保存为 YAML，查询与导出 JSON 为派生产物 |
| D04 | 核心优先 Rust，独立脚本优先现代 Python | 当前直接用 Rust 完成采集、校验和导出，尚无 Python 包装层 |
| D05 | Python 依赖、锁文件与 legacy 导出一致 | 独立 Python 任务出现后遵守 `pyproject.toml`、`uv.lock`、`requirements.txt` 约定 |
| D06 | 项目跟踪与研究目录分开，持续维护树形索引 | `project/` 保存现状，`research/` 保留研究，`docs/` 解释实现与维护 |
| D07 | 官方发布材料优先，博客保留关键原文，模型卡和详情页提取结构化内容 | 保留完整选定段落、作用域和证据，按字段生成官方优先的选择结果 |
| D08 | 在本地分支修改和验证 | 后续工作不创建 PR 或推送远程，除非用户重新明确要求 |
| D09 | 用独立 HTTP Mock 服务替代测试中的真实模型调用 | 保留提供方原生协议、参数限制、错误、SSE 和工具多轮关系，响应内容使用合成数据 |
| D10 | 先覆盖 AA Intelligence Index 前 20 个变体，前 50 名与真实 token 验证列入待办 | 固定排名快照与选择口径，未确认接口或参数对应关系保留缺口，本轮不执行真实推理 |

## 已采用的实现选择

| 编号 | 决定 | 依据与边界 |
| --- | --- | --- |
| I01 | Rust CLI 使用 Tokio、reqwest、Serde、serde-saphyr 与 schemars，依赖锁定到 `Cargo.lock` | 采用单一核心；受限 YAML 输入还通过解析事件检查语法 |
| I02 | 每个来源一个 `Catalog` YAML，格式版本为 1 | 记录来源快照与原值，便于按来源更新和审查 |
| I03 | 来源记录 ID 使用 `<source>:<kind>:<upstream_id>` | 来源记录数与人工审查的模型身份数分别统计；同名不构成身份依据 |
| I04 | 模型身份和接口绑定保存在独立的身份文件中 | 模型身份只收纳模型记录，接口只绑定服务记录；按记录查询规则时仅使用该记录的显式绑定 |
| I05 | 导入字段保留 JSON 原值和绝对 JSON Pointer | 缺失不转为否定，平台限制和价格保留来源作用域 |
| I06 | 默认公开同步 models.dev、HF、ModelScope、OpenRouter、Vercel 和 `official` 六个来源 | HF 与 ModelScope 使用精选清单，官方页面使用显式页面配置；`discover` 先输出候选供审查；认证来源需显式选择和启用 |
| I07 | 原始响应按 SHA-256 保存，API JSON 位于 `.cache/snapshots/`，HTML、Markdown 与 PDF 字节位于 `.cache/documents/` | `evidence archive` 和 `evidence restore` 复制 `.json` 与 `.bin`，保留失败页面响应并重放有效提取；manifest 关联数据版本，原始缓存不进入 Git |
| I08 | 完整目录需全部分页成功，精选仓库按条隔离失败，每个来源校验后原子保存 | 失败项保留旧记录并保存本轮错误，成功项可更新；命令存在失败时返回非零状态 |
| I09 | 保留遗漏记录与未变化记录的旧证据，并保存最近采集尝试的范围和状态 | `completed_at` 表示最近尝试，`last_successful_at` 表示最近整个范围完成；返回、完整目录缺席、未请求、失败和未知分别呈现，均不自动证明退役 |
| I10 | 人工声明按独立作用域求值，保留条件、审查状态和文档证据 | `rules` 区分条件不匹配、缺少上下文、已知结论与冲突；当前证据均为 `reported`，求值不会升级为推理实测 |
| I11 | 14 个 JSON Schema 从 Rust 类型生成，CLI 另做语义校验 | 包含官方页面配置、文档目录、文档对照、字段选择与 mock 配置；schema 一致性、结构校验和本地证据核对分别提供命令 |
| I12 | 导出确定性 JSON，查询和统计由 CLI 提供 | 导出保留原始记录、领域视图、身份和关系，并加入 `official_sources`、`documents`、`document_comparisons` 与 `resolved_metadata` |
| I13 | 从已知来源字段派生有类型的领域字段 | 任务保留来源分类，模态、上限、参数、能力、谱系和价格保留 `fact` 与原始快照指针；未知标签与价格条件继续保留，缺失字段不命中过滤条件 |
| I14 | 从显式字段派生 `serves`、`references` 和 `derived_from` | 每条关系保留证据与目标是否已收录；仓库引用和父模型关系不会触发身份合并或能力继承 |
| I15 | 14 个来源的范围、认证约定和条款状态集中记录，其中 6 个为公开来源 | `sources` 读取 `config/sources.yaml`；该描述不覆盖可执行端点，也不把认证来源纳入公开发现 |
| I16 | 专业模型条件精确到模型变体、表示或 checkpoint | 动作 tokenizer、机器人动作、蛋白质结构和医学分割均保留作者声明的范围；仓库内多个权重文件的专长通过条件分别表达 |
| I17 | 官方页面通过 `documents sync/list/check` 采集、查看和对照，页面仅绑定明确的模型记录 | 页面日期与模型发布日期分别记录；提取结果保留原文定位、精度和文字条件，不覆盖 API 事实或人工规则 |
| I18 | 官方字段只与精确绑定记录的同名事实对照 | 近似值、条件和失败后保留的旧内容保留各自状态；差异不自动裁定来源正误，最近失败保留错误和可用旧内容 |
| I19 | 字段选择按模型卡、详情或文档，再发布博客，再目录事实的顺序处理 | 限同型号、模型作用域；同等级冲突或只有带条件、近似、旧内容时不直接采用；所有候选仍保留 |
| I20 | 官方模型声明可通过已审查的模型身份共享 | 接口声明和服务限制分别保留；不沿服务引用、别名或近似名称传播 |
| I21 | `documents reparse` 从缓存离线重建完整提取 | 校验来源与内容摘要，全部页面处理成功后原子保存；不改变采集时间和失败记录 |
| I22 | 官方目录页保存未绑定的候选链接，型号页面恰好绑定一个模型记录 | 目录候选保存标签、URL 和证据；不自动跟进链接、创建记录或把系列字段复制给多个型号 |
| I23 | Vercel 匿名目录的条目保存为服务记录 | 保留类型、模态、限制与平台声明；价格口径未经确认时保留未分类原值，目录时间戳不改作模型发布日期 |
| I24 | `mock serve` 通过 Axum 提供选定提供方的原生 HTTP 协议 | 内置配置随二进制发布，使用合成认证，不请求上游；未实现功能明确返回 501 |
| I25 | 会话使用确定性场景、顺序脚本和有 seed 的覆盖序列 | 校验失败保留步骤，合成 HTTP 错误推进步骤，工具结果续轮保留主序列位置；跳过和待执行项独立记录 |
| I26 | AA 排名选择单位是评测变体，接口绑定保留精确服务 ID 和证据 | 前 20 名涉及 8 个基础模型候选、7 个原生接口模型；Muse Wonder Full 保留公开 API 缺口，effort/fallback 对应仍未知 |
| I27 | 模型限制按提供方、接口和明确型号配置，结构化输出使用受限生成与 schema 校验 | 不将网关能力、相近型号或未知字段自动提升为原生模型契约；不访问外部 schema URL |
| I28 | 显式启用 JSON 浮点数 roundtrip 解析，证据回放仍要求值严格相等 | JSON 与 YAML 保存同一浮点值；旧记录的舍入差异按已核验摘要的原始快照恢复，保留来源与采集时间 |
| I29 | 证据校验核对来源记录的 ID、名称及合法回退规则 | 字段指针正确不能替代身份证据；适配器增加映射通过显式离线重归一化迁移，保留原获取时间与同步清单 |
| I30 | 页面成功由来源身份与结构契约共同判断，HTTP 200 不能单独代表成功 | 应用壳和提取退化复用失败保留路径，失败响应保存为 `failed_snapshot`；目录与发布页按各自契约验收 |
| I31 | 仓库模型卡支持跟踪引用和固定提交，每轮按解析出的提交采集 | `repository` 明确 repo/path/revision；快照保存实际 URL 和 `upstream_revision`，历史回放不依赖当前分支头 |
| I32 | 最近观察状态参与查询、导出和模型字段选择 | 缺席、失败与未请求的目录候选不直接选定；旧清单缺少范围或状态时保持 `unknown` 并保留原有查询，要求本轮返回时筛选 `observed` |
| I33 | 暂时网络错误与限流采用有总时限的重试，匿名文档按厂商允许的 URL 逐跳检查 | API 与认证请求继续拒绝重定向；PDF 用内置 Rust 解析器保存选定文本和页码，扫描页不自动执行 OCR |
| I34 | 先补已有 HF 快照字段，再按缺口接入新来源 | 许可证、量化、Tokenizer、运行信息、数据集和文件清单保留原值与指针；新文件必须关联自己的快照 |
| I35 | CI 通过显式 URL 与 SHA-256 恢复与当前数据版本对应的证据包 | 使用归档 manifest 和严格解包；托管位置与发布范围未确定前明确标记待配置，本轮不自动上传 |

## 尚待决定或验证

- 扩展已审查身份的覆盖范围，尤其滚动别名、量化、镜像仓库与具体权重版本。
- 继续核对来源任务分类、专业模型输入输出表示和未分类价格字段的映射范围。
- 各来源可公开保存和再分发的范围，以及注册表整体的许可证。
- 认证目录的真实账户范围、配额、分页行为与字段可用性。
- 为已有快照归档恢复命令确定长期存放位置、保留范围与清理策略。
- 依据明确采集范围与观察状态设计退役复核和过期提醒，不把失败、缺席或未请求自动视为退役。
- 按元信息采集计划接入网关端点、区域价格、原生目录与评测引用，先验证单位、范围、版本和证据归属。
- 扩展 AA Intelligence Index 前 50 名的接口与行为覆盖，核查精确 effort/fallback 参数对应。
- 设计真实 token 探针及 `observed` 证据结构，另行明确授权、费用、脱敏与复现条件。
- 覆盖扩展、更新频率与长期维护的验收标准。

先依据实际来源变化和使用需求处理这些问题。
查询 API、SQLite 发布物、网站、浏览器采集和工作流平台仍属于后续可选扩展。
