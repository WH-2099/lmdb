本计划把元信息采集研究拆为当前修复、数据迁移和后续接入任务。
本轮代码修复、数据迁移与本地证据归档恢复已完成，实际结果统一记录在[项目进度](../project/roadmap.md)。

## 本轮交付与依赖

| 阶段 | 工作 | 前置条件 | 验收产物 |
| --- | --- | --- | --- |
| A：证据与失败处理 | 核对记录身份和名称；拒绝应用壳与结构退化；跟踪仓库引用并固定本轮提交；记录采集范围、结果与逐项失败 | 现有来源配置、快照和历史目录可读 | 错误身份被拒绝，页面失败保留旧内容，精选列表部分失败可保存成功项，查询能解释每条记录的观察状态 |
| B：已有字段与迁移 | 补齐 HF 快照中的许可证、Tokenizer、运行入口、量化、语言、数据集、版本和文件清单字段；提供离线重归一化 | A 的身份证据校验可用；原始响应摘要正确 | 新字段各自保留原值与 JSON Pointer，旧记录按明确命令迁移，证据日期与最近观察时间各自保留 |
| C：采集传输与文档格式 | 为暂时网络故障、限流和逐跳重定向设置边界；支持 PDF 字节、文本与页码证据 | A 的失败保留行为通过回归；允许访问的页面来源已配置 | 重试有总时限，跨主机跳转受允许列表约束，PDF 可离线重放且失败不会覆盖有效内容 |
| D：可重复验收 | 生成 schema，回放已有缓存，重建导出，连接证据归档与 CI 校验入口 | A 至 C 合并；迁移后的目录和文档通过语义校验 | 本地全量证据校验与空缓存恢复成功，CI 能根据显式配置恢复并核对对应数据版本的证据包 |

A 的身份、页面和同步状态修复可并行开发，但 B 的数据写入必须使用完成后的校验器。
C 的传输与 PDF 工作可并行开发，最终通过 A 的失败保留路径保存结果。
D 需要在最终数据迁移后运行，不能用旧目录的通过记录替代新数据验收。
长期归档存放位置尚未确定，CI 接口完成与远程证据托管启用分别验收。

## 必须保持的数据含义

来源记录、跨来源模型身份、托管服务、权重仓库和评测主体各有自己的范围。
名称相同、链接相同或一个模型的服务价格存在，都不足以建立身份或账户可用性。
目录原值、官方文档声明与真实行为观察保留各自证据等级。

| 情况 | 保存与选择规则 |
| --- | --- |
| 字段没有返回 | 保持未知，不能填 `false`、`0`、空集合或邻近型号的值 |
| 来源间数值冲突 | 保留双方原值、单位、作用域和条件；字段选择报告冲突，不能默认采用较大值 |
| 完整目录成功但记录缺席 | 保留历史记录并标记本轮缺席；没有退役证据时不写退役状态 |
| 精选记录请求失败 | 保留旧记录与失败原因；其他成功记录可以更新，命令仍报告部分失败 |
| 记录退出精选清单 | 标记本轮未请求；不能把采集范围变化解释为上游删除 |
| 旧同步清单缺少范围或完成状态 | 观察状态保持未知；不能通过离线迁移补写本轮网络观察 |
| 页面身份或结构不符合预期 | 记录失败并保留同一来源定义下的旧内容；零字段是否有效由页面类型和提取契约判断 |
| 仓库引用可移动 | 每轮解析到具体提交；同轮文件使用该提交，历史证据继续引用原提交 |
| 文件来自不同响应 | 每份响应使用自己的 snapshot、路径或指针；不能把配置文件中的值定位到目录 API |
| 评测设置缺失 | effort、tools、样本量、版本、测量窗口等字段保持未知；模型名称中的括号不能替代请求参数证据 |

最近观察状态参与查询、导出和字段选择。
缺席、失败或未请求的历史目录值仍可供审查，但不参与有效目录值的选择。
`unknown` 的历史值仍可参与原有查询与选择，输出保留未知状态；需要本轮成功观察的消费方应筛选 `observed`。
官方页面的有效性按自己的获取与提取状态判断。
具体字段、观察状态和命令以[数据模型](data-model.md)、[领域字段](domain-fields.md)及[维护流程](maintenance.md)为准。

## 数据迁移顺序

1. 在修改数据前保存当前 Git 版本，并对现有引用的原始响应运行证据归档。
2. 更新 Rust 类型、适配器、校验器与 schema，再运行针对身份、退化、部分失败、重试和 PDF 的回归。
3. 对已经缓存的 API 响应执行 `renormalize --source huggingface`，只从记录自身引用的响应增加或修正字段。
4. 对已有页面执行离线重解析，核对原始字节与提取版本，保存新的完整提取结果。
5. 同一 HF 文件的历史固定 SHA 描述可在严格核对身份、路径与旧快照后离线迁移为跟踪描述；需要观察当前引用时再单独同步并记录当轮提交。
6. 检查目录、页面、配置和 schema 的 diff，核对记录 ID、字段原值、绑定、删除项、条件与观察状态。
7. 运行完整检查、证据校验与导出，再把该 Git 数据版本和证据归档关联起来，验证空缓存恢复。

离线迁移不刷新 `retrieved_at`、采集尝试时间或最近同步清单，不把解析器升级当作重新观察上游。
缺少或损坏的缓存应使对应迁移失败；先补回精确历史证据再继续，不能用当前响应冒充旧响应。
新增字段映射本身不使旧事实失真，身份证据校验应允许合法的名称回退规则。
迁移造成的变更与后续在线刷新分别记录，避免把字段覆盖提升全部归因于新采集。
归档准备期间保留原缓存，证据包上传与远程保存需先确定目标、访问范围和保留策略。

## 本轮验收矩阵

| 风险 | 最小有效验证 |
| --- | --- |
| 身份归属错误 | 原文正确而 `upstream_id` 或名称被改写时失败；合法名称回退通过；原字段仍逐值核对 |
| 页面覆盖有效历史 | 有效页面 → 应用壳或型号不符 → 正常页面，分别保存成功、失败与恢复，失败阶段保留原内容 |
| 仓库引用变化 | 跟踪引用从提交 A 更新到 B；新响应使用 B，A 的缓存仍能离线重放；显式固定引用保持固定 |
| 精选来源部分失败 | 三个仓库中一个失败，另外两个更新；失败项旧证据保留，清单标为部分完成，退出清单项为未请求 |
| 完整目录失败 | 任意分页失败、重复 ID 或悬空模型引用时保留旧记录，不能声明完整或批量制造缺席；完整成功后才能确定缺席集合 |
| 观察状态消费遗漏 | `query`、`inspect`、导出和字段选择使用一致状态；历史缺席值不会默认为当前选定值 |
| HTTP 重试与跳转 | 暂时断流可恢复；超过时限、错误主机或跳转上限失败；认证请求不向其他主机传播凭据 |
| PDF 证据 | 页码能定位提取文本，原始 PDF 摘要可由内置解析器重放；损坏文件或解析失败保留旧内容 |
| HF 字段覆盖 | 用当前 151 份历史快照核对新增字段原值与指针，并记录实际新增数量；配置 dtype 与量化方法分别保存 |
| 数据可复现 | 最终目录通过 `validate --evidence`；空缓存恢复后重新校验，导出与原目录逐字节相同 |

运行结果在[项目进度](../project/roadmap.md)记录实际命令、测试数量、数据版本和失败项。
合成响应测试说明代码在给定场景下的行为，在线成功只说明该来源在本次环境与范围内可访问。
需要凭据的目录和真实推理仍保留各自的待验证状态。

## 后续来源接入任务

每项先写入来源契约和合成样本，再实现有范围的采集、证据校验、失败保留及导出。
访问条件、API 版本、单位、分页和来源声明发生变化时应重新核对一手文档。

## 接入完成的共同条件

- 来源配置明确公开或认证访问、账户与地域范围、API 版本、许可调查状态及更新入口。
- 原始响应可按摘要保存与回放，分页和精选范围能区分完整、部分、失败和未请求。
- 每个事实可回到自己的响应、指针或页面定位，单位和条件在类型投影中继续保留。
- 通过成功、空结果、字段缺失、错误身份、限流和部分失败的必要回归，并记录实际在线验证范围。
- 数据迁移、schema、查询、导出和维护文档一起交付，未确认的来源字段保留未知或原值。
- 公共数据发布前确认实际内容的保存与再分发范围；代码许可、权重许可、目录许可和评测数据许可分别判断。

计划不以来源数量作为完成标准。
下一来源应能回答现有字段、服务范围或证据质量上的具体缺口，并有可独立检查的验收样本。
