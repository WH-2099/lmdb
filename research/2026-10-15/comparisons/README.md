# 同类项目与复用判断

调研日期：2026-10-15。
状态：第一轮调研，尚未决定最终 schema 或实现方案。

本目录回答两个问题：现有项目已经解决哪些问题，以及 LMDB 还有哪些经过证据支持的建设空间。

## 阅读顺序

1. 阅读 [项目对比与代码考察](projects.md) 的决策摘要和总表。
2. 重点查看 models.dev、LiteLLM、genai-prices 与 LLM Registry 的维护方式和证据粒度。
3. 回到[本轮调研索引](../README.md)，结合[数据源调研](../sources/README.md)和[架构研究](../architecture/README.md)讨论范围。

## 当前判断

如果第一版只收集名称、模态、上下文、价格和常见能力，优先使用或补充 models.dev 等现有目录。
models.dev 已经区分模型本体和提供方条目，并提供继承关系、统一标识与同步流程。
LMDB 是否需要独立存在，应通过“某个字段来自什么证据、在什么接口和版本下成立、矛盾如何保留、未知如何表达”这些具体用例验证。

现有项目也已实现部分条件价格、来源 URL 和结果级验证状态。
因此，不能把“有来源”或“能写条件”本身视为 LMDB 的独有价值。
本轮在重点阅读的 schema 中尚未发现同时覆盖全类别模型、逐字段证据和 `role × modality × endpoint × version` 条件限制的完整方案。
这是一项有范围的调研判断，不是对所有开源项目的穷尽证明。

## 后续维护

- 新项目先追加到 `projects.md`，记录检查日期、第一手来源和实际检查范围。
- 代码结论尽量使用固定 commit 的链接。
- 文档声明、代码观察与本项目建议分别标明。
- 上游增加能力时，更新复用判断，避免为旧差距继续建设。
- 数据再分发许可单独记录，不从 SDK 或爬取工具许可证推导上游内容权限。

本轮只读检查了三个上游仓库，没有安装依赖或执行其程序。
公开 API 文档和仓库会继续变化，后续选型前应复核相应快照。
