## 方法

优先通过 Anysearch 查找官方文档、规范、发布说明和维护者仓库，再读取原文。
搜索摘要仅作为线索，核心结论以文档正文、公开 API 响应或固定提交源码为依据。
网页提取失败或内容被截断时，尝试官方原始文件、普通 HTTPS 读取或其他只读浏览方式。
访问失败只说明本次环境无法取得资料，不等于源服务对所有用户不可用。

API 采样限制在少量公开元数据请求，不穷举目录，不请求权重，也不调用付费推理接口。
现有裸仓可用时先更新后复用，否则在 `/tmp/lmdb-research/` 做临时克隆。
源码考察不执行上游程序，不安装被调查项目的依赖。
报告保留 URL、提交号与必要定位，阅读报告不依赖临时目录继续存在。

## 如何理解验证程度

| 记录方式 | 能说明什么 | 不能说明什么 |
| --- | --- | --- |
| 官方文档已读 | 发布者当前描述的行为或字段 | 每个账号、地区、模型版本的实际行为 |
| API 只读采样 | 指定请求在指定时刻返回的形状与状态 | 全目录完整性、长期可用性或付费权限 |
| 固定提交源码 | 该提交实现了哪些字段、流程和验证 | 已部署服务必定运行该提交 |
| 文档与示例冲突 | 存在需要核对的资料差异 | 任意一边自动正确 |
| 设计建议 | 基于已发现问题提出的架构取舍 | 已被实现或性能已经达标 |
| 未核实 | 需要权限、更多证据或下一轮实验 | 可以按常见做法填入默认值 |

报告中出现的模型数、限流额度和版本号是访问时观察，不能当作永久常量。
官方页面的发布日期、网页检索时间和本轮获取日期可能不同，应优先保留来源自己的版本标识。
